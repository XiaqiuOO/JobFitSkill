# JobFitSkill｜简历定向改写

> **市面上的简历工具帮你"改得更好看"，JobFitSkill 帮你"改得更对路"**——在不虚构、可背调的前提下，用真实岗位画像把同一段经历重写成目标岗位想要的样子，并告诉你还差什么、还能投哪里。

这是一个可被任意 AI Agent（Claude Code、Cursor、Trae、Codex 等）直接调用的 Skill：把一份现有简历 + 一个目标 JD（或一个投递方向）变成 **一份改好的 Word 简历 + 一份契合度诊断 + 一份可投岗位清单**。

---

## 它解决什么问题

大多数"简历修改"工具做的是**关键词替换和语言润色**：把 JD 里的词塞进简历，读起来很像，但面试官追问两句就露馅。

JobFitSkill 多做四件事：

| 常见做法 | JobFitSkill |
|----------|-------------|
| 凭感觉换几个词 | 先建立**五层岗位画像**（门槛 / 职责 / 能力 / 素质 / 语境），再决定改什么 |
| 把"参与"写成"主导" | **角色强度只能降级或同级**，每条新句都能在溯源表里找到原句依据 |
| 只给一份看起来还行的 PDF | **只输出改好的 Word**，在原文件里原位替换，页数、字体、板块顺序与原件一致 |
| 改完就结束 | 给出**可复现的契合度评分、Gap 清单、面试追问风险**，并检索最多 10 个相似在招岗位 |

---

## 核心能力

- **两种模式，不混用**
  - `A 具体 JD 模式`：按某家公司某个岗位的 JD 定向改写，结合公司业务语境建模。
  - `B 投递方向模式`：如"产品经理 → 行业研究"，先检索 ≥20 家公司官网 JD，按频次统计出方向画像，再做能力迁移。
  - 用户没说明模式时，Skill 会**先问**，不会默认。
- **真实性硬约束 + 实质改写**：只锁死数字、岗位名、公司、时间、学历、专业；措辞、详略、行业语言可大改，经历板块必须贴合画像，改完与原表述相似度 <80% 才算有效。
- **反 AI 味**：12 项体检 + 硬禁词表 + 行业语域表；允许"闭环 / 跑通 / 复盘"等行业真实术语，但禁止"跑了 / 拉了 / 搞定"这类口语。
- **可复现评分**：五维固定清单与公式（硬门槛 25% / 核心职责 30% / 证据强度 20% / 认知 15% / 表达 10%），换人或换 Agent 都能算出同一个分。
- **Word 优先排版**：输入只收 Word、输出只出 Word，直接在原文件里原位替换；脚本仅在无原版 Word 时兜底。
- **机会扩展**：改完后输出最多 10 个相似在招岗位，五列表格（公司｜官网岗位名｜能力画像｜契合度｜链接），链接均需本次核验。

---

## 改写原则（硬要求）

1. **输入只收 Word、输出只出 Word**：不重建版式，直接在原 Word 里原位替换；交付前必须自查空白与美观，不留格式问题给用户。
2. **经历要实质改写**：实习/工作经历是全简历核心，必须贴合目标画像重写，改完与原表述相似度 <80%；只锁死数字、岗位名、公司、时间、学历、专业。
3. **板块职责分离**：自我评价、技能等非经历板块不复述项目；自我评价固定两点（专业能力 + 综合素质），抽象概括。
4. **要写出深度**：每条经历回答"做了什么 → 在目标岗位里叫什么 → 产出/被谁用"；技能写出能力边界，而非堆名词。
5. **排版先探测再动手**：先探测 Word / python-docx，锁定唯一路径，失败即停，不在工具间反复试错、反复安装软件。

## 工作流

```
S0 收件解析 → S1 模式选择 → S2 画像研究 → S3 重写 → S4 文字稿确认
   → S5 排版导出 → S6 质检 → S7 契合度诊断 → S8 相似岗位 → S9 交付
```

五道门禁（不满足不进入下一步）：

1. **G1 模式**：用户已明确选 A 还是 B。
2. **G2 素材与画像**：JD 要素齐，或方向画像成型。
3. **G3 文字稿**：用户已明确同意排版。
4. **G4 版式**：页数与原件一致，无畸形留白。
5. **G5 链接**：相似岗位链接本次均可访问。

除 S4 需要停下来等确认外，其余阶段连续执行，不逐步请示。

## 安装

**方式一：把 GitHub 链接直接发给你的 AI Agent（最省事）**

把仓库链接发给 Claude Code、Codex、Cursor、Trae 等任一支持 Skill 的 Agent，只需发送一句安装要求即可：

```text
帮我安装这个 Skill：https://github.com/XiaqiuOO/JobFitSkill
```

**方式二：手动放进 Skills 目录**

下载仓库后，把整个 `JobFitSkill/` 目录放进对应 Agent 的 Skills 目录：

```bash
# 以 Trae 为例
cp -r JobFitSkill ~/.trae/skills/JobFitSkill

# 以 Claude Code 为例（项目级）
mkdir -p .claude/skills && cp -r JobFitSkill .claude/skills/
```

要求：

- Microsoft Word（直接编辑原文件，首选）
- Python 3.9+ 与 `python-docx`（仅「无原版 Word」的脚本兜底时需要）

```bash
pip install python-docx
```

## 使用

直接用自然语言触发：

```
帮我按这个 JD 改一下简历（附简历 + JD 截图）
```

```
我是产品经理方向，想转投行业研究，帮我改简历
```

Skill 会：

1. 解析你的简历，确认模式；
2. 建立目标岗位画像（JD 模式）或检索 ≥20 家官网 JD（方向模式）；
3. 在对话框给出**完整文字稿 + 改动说明**，等你确认；
4. 确认后输出改好的 Word（DOCX）；
5. 给出契合度评分、Gap、面试追问风险；
6. 给出最多 10 个相似岗位链接。

## 排版脚本用法

```bash
python3 scripts/build_resume.py \
  --spec /path/to/resume_spec.json \
  --out /path/to/姓名_目标岗位_简历.docx
```

最小 spec 结构：

```json
{
  "page": {
    "size": "A4",
    "pages": 1,
    "margins_cm": { "top": 1.9, "bottom": 1.7, "left": 2.0, "right": 2.0 }
  },
  "style": {
    "cjk_font": "Noto Sans CJK SC",
    "latin_font": "Liberation Serif",
    "body_size": 10.5,
    "date_size": 10,
    "heading_size": 11,
    "name_size": 19,
    "line_spacing": 1.15,
    "space_after": 2,
    "heading_space_before": 8,
    "bullet_indent_cm": 0.42
  },
  "header": {
    "name": "张三",
    "contact": "138-0000-0000 ｜ zhang@example.com ｜ 上海 ｜ 求职意向：行业研究"
  },
  "blocks": [
    { "type": "heading", "text": "教育背景" },
    { "type": "entry", "left": "某某大学 ｜ 金融学 本科", "right": "2022.09–2026.06" },
    { "type": "bullet", "text": "GPA 3.7/4.0（专业前 10%）" }
  ]
}
```

可选字段：

- `style.accent_color`：主题色，如 `[0, 84, 150]` 或 `"#005496"`。
- `header.photo`：`{"path": "...", "width_cm": 2.5}`，仅在原件有照片时使用。
- `page.pages`：原件页数，脚本会据此校验并给出 `[WARN]`。

支持的 block 类型：`heading`、`entry`、`bullet`、`kv`、`para`、`space`；文本中可用 `**加粗**`。

## 契合度评分口径

```
总分 = 硬门槛 ×25% + 核心职责 ×30% + 证据强度 ×20% + 认知 ×15% + 表达 ×10%
```

每一维都按固定清单逐项打分后再换算，**不允许凭感觉直接给总分**。输出必须带明细，且改写前会先用同一口径给原版打分，便于对比提升来源。

分数带：`85–100 强匹配`｜`70–84 较匹配`｜`55–69 有机会`｜`40–54 偏弱`｜`<40 不建议主投`。

> 这是文本匹配度评估，不是录用概率预测。

## 话术与边界

**会做**

- 大改措辞、详略与顺序，把每段经历重写成目标岗位的语言（这是核心动作）；
- 用能力桥把"用户调研"翻译成"用户分层依据"这类行业说法；
- 补充你口头确认过的细节（工具、人数、周期、产出）；
- 新增"求职意向"定位信息；自我评价只写「专业能力 + 综合素质」两点，技能只罗列能力、不复述项目。

**不会做**

- 编造公司、项目、证书、奖项、数字（这是唯一锁死的部分）；
- 把"参与/协助"升级成"负责/主导"；
- 改岗位名称、部门、时间、学历、专业；
- 代投递、代填网申、伪造背调材料。

**已知边界**

- 只接受 Word（DOCX）输入；收到 PDF / 图片 / 纯文本时会先请你发 Word 版，拿不到才重建版式（照片、复杂表格、图标无法 1:1 还原，会明确告知）。
- 相似岗位依赖当前检索工具与招聘窗口；岗位下架或链接失效时会说明，不编造 URL。
- 官网 JD 通常可公开访问；偶发反爬时会换检索式或官方公众号入口重试。
